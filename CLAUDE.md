# KSK Attendance MiniApp (Maharashtra)

A mobile-first attendance MiniApp for **ITI craft instructors and principals in Maharashtra**, opened inside the **SwiftChat Android WebView**. Instructors mark student attendance once per batch (or per half-day / period, by configuration). Principals see the whole institute, mark staff, and correct same-day mistakes with a reason and an audit trail. This build runs on **mock data on the device** or on a **shared Supabase demo backend**, both behind repository interfaces, with a floating **demo panel** for stakeholder demos. Real APIs plug in later without UI changes.

## Sources of truth (in this order)

1. `Doc/PRD.pdf`: product rules, configuration registry, invariants.
2. `prototype/Prototype.html`: the approved clickable prototype. It is authoritative for layout, copy and flow.
3. `Doc/swiftchat-design-system.md`: SwiftChat DS. It is authoritative for tokens and components. Use light mode only.
4. `Doc/mh_ksk_logo.png`: the brand logo. **Never modify the original.** Derived icons come from `npm run icons`.

`Doc/swiftchat.png` was referenced by the brief but is missing (see `docs/DECISIONS.md` D-004). Features the PRD doesn't have (Home announcements, per-batch refresh, the at-risk report, the monthly register download, Voice Agent, the Supabase backend, own attendance before students, the staff report card) are extensions, recorded in D-053–D-055 and D-078–D-159.

Deeper docs are in `docs/`: PRODUCT_CONTEXT, ARCHITECTURE, DESIGN_SYSTEM, CONFIGURATION, DATA_MODEL, DEMO_GUIDE, TESTING, DECISIONS, SUPABASE. Voice Agent has its own folder, `docs/voice/` (design spec, plan, `REPO_MAP.md`, `RUNBOOK.md`). `.gitignore` ignores `/docs`, so only the eight files that were already tracked are in git: `docs/SUPABASE.md` and `docs/voice/*` are local-only until added with `git add -f`.

```bash

npm test             # Vitest: unit + integration (tests/unit, tests/integration)
npm run e2e          # Playwright: builds, serves on :3200, Pixel 5 at 360px, Asia/Kolkata
npm run build        # production build (all pages static, one route handler: /api/voice/token); prebuild runs scripts/vendor-mediapipe.mjs
npm run check        # lint + typecheck + test + build
npm run check:demo   # builds with NEXT_PUBLIC_DEMO_MODE=false into .next-nodemo and greps that no demo code shipped
npm run icons        # regenerate public/branding/* and src/app/{icon,apple-icon}.png, favicon.ico from the logo
npm run test:voice-live    # opt-in: text turns through the real executor and gemini-3.8-live (needs GEMINI_API_KEY in .env.development)
npm run voice:spike-token  # opt-in: mint a token, connect, time to first audio
npm run voice:spike-voices # opt-in: render one English and one Marathi line with the persona in 9 candidate voices (Achernar first) to WAV in os.tmpdir()/ksk-voice-spike
npm run voice:ui-rehearsal -- <scenario.json> [--base <url>]  # opt-in, macOS: speaks the trainer's lines with `say` into Chromium's fake microphone against a running server with GEMINI_API_KEY; scenarios in scripts/voice/rehearsals/; log and screenshots in os.tmpdir()/ksk-voice-rehearsal/<name>
npm run test:supabase-live # opt-in: the app's Supabase repositories against the live project, test institute 99999 only (needs NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY)
```

`.env.development` is git-ignored, so a fresh clone has none: `cp .env.example .env.development`, then set `GEMINI_API_KEY=`. Without the file the three voice commands stop with "not found" (Node's `--env-file`); with the file but no key, `test:voice-live` skips. `voice:ui-rehearsal` reads no env file: it drives a server you started (`next start` accepts `node --env-file=…`; `next dev` refuses it, so keep the key in the project's `.env.development`), and each run spends Gemini usage. `test:supabase-live` reads the Supabase URL and key from `.env.development.local` or `.env.development` (the `.local` file wins) and skips without them.

The Node range is `>=20.9 <27`. This is Next.js **16** with React 19.2. Read `node_modules/next/dist/docs/` before using an unfamiliar API (see AGENTS.md).

## Architecture rules (enforced by ESLint; see `eslint.config.mjs`)

```
UI (src/app, src/features, src/components, src/hooks)
  → services (src/services)          ← composition root: src/services/container.ts
    → repository interfaces (src/repositories/interfaces)
      → mock impl (src/repositories/mock) | Supabase impl (src/repositories/supabase) | API impl (src/repositories/api, stubs)
domain (src/domain) and config (src/config) are pure TypeScript: no React, Next, services or storage.
```

- The UI **never** imports `@/data/*`, `@/repositories/mock|api|supabase`, `@supabase/*`, `@/demo/*` or `@/server/*`. It reads data only through `useServices()` / `useQuery()`. `src/repositories/supabase` is one more repository implementation: only the composition root (`container.ts`), `src/app-shell/boot.ts` and the demo seeder (`src/demo/supabase-seeder.ts`) reach it, and only `src/repositories/supabase/client.ts` imports the SDK (`@supabase/supabase-js`, pinned to `2.117.2`), loaded by `import()` for the Supabase source only.
- `src/server` (voice token mint and guards) is server-only: only `src/app/api/**` may import it, and it never imports React, hooks, components, features, services, demo code, mock data or mock repositories.
- The UI **never branches on a role or a person**. `journey.isPrincipal` is lint-forbidden in UI code. Voice exists only when `journey.voice.enabled`, and what it can do comes from its capability plan (D-139). Screens read capabilities from `useJourney()` (`src/config/journey.ts` is the only place that decides what exists). A disabled feature is *absent*, not hidden.
- Integrity rules (submit once, no backdating, principal-only same-day corrections with a reason, time fence, verification before the list, one staff mark per day, own attendance before students) live in `src/domain/rules.ts`. Services and repositories enforce them. Hiding a button is never the only guard.
- **Own attendance first (D-152).** With `staff.selfBeforeStudents` (Maharashtra on), no batch opens, verifies or submits (tap, voice or a typed URL) until the user's own staff record for today exists (a principal's mark counts): `checkSelfFirst` refuses `self_first` in the batch-opening path, `openRoster` and `submit`. Home shows My attendance first, rows say "Mark your attendance first" and a typed gateway URL shows the problem screen. `verification.selfPassReuseMinutes` (Maharashtra 10, 0 off) lets a same-day self pass that covered every check the batch needs open the next batch without a second check ("Verified a moment ago"). The principal never has self attendance and is unaffected.
- **One submit confirmation (D-149).** The Review screen is the confirmation: its Submit attendance saves at once (a synchronous guard makes a double tap save once) under the note "After you submit, this attendance can't be edited." There is no "Submit attendance?" sheet (a deliberate deviation from the prototype); the correction and staff sheets stay, each the only confirmation. The record screen shows only the session it was opened for: there is no Today/Yesterday switch, and a typed past-date URL renders read-only (D-150).
- Corrections are append-only. The original submission is never modified. `effectiveMarks()` folds corrections over it.
- All dates and times are IST (`src/lib/time.ts`). Inject `Clock`; never call `new Date()` in domain code. `ctx.wallClock` is the real time of day, for greetings only: `dayPart(instant)` (morning 05:00, afternoon 12:00, evening 17:00, night 21:00) drives Home's greeting and the spoken one, while batch windows, cards and rules keep `ctx.clock` (the demo clock in a demo; production passes the same clock for both, D-151).
- CSS Modules only. Every colour, radius, type size and spacing value is a token from `src/styles/tokens.css` / `typography.css` (a unit test lints this). No UI libraries.
- Files over 300 lines trigger a lint warning. Split them.

## SwiftChat Design System rule

Use SwiftChat semantic tokens and the kit in `src/components/ui`. Montserrat is the English font and Mukta the Marathi font (`:lang(mr)` switches the type variables). Status is always icon + text + colour. Every roster that marks attendance uses `AttendanceStatusSelect` (one native select per person, options only from configuration, OJT and saved marks as `LockedStatus`, D-062) on a white row (no status tints; follow-ups inside the row, D-070). Every attendance total uses `AttendanceSummary` (one tile per configured status; Present counts by presence weight, half day ½ and OJT 1, D-069). Short row states use `StatusLine`, quiet guidance `InlineNote`, list cards `Card divided`, and waiting records the `SyncPendingCard` (D-064, D-068). Home never manages offline data (D-071); its Sync pending card only links "See what's waiting" to Offline data (D-153). A screen's view switch is a `md` `Segmented` spanning the column, a filter a `sm` one spanning it, and a control inside a panel or row `sm` at natural width from 600px; the roster, the record and the principal's Students and Staff views share one fixed band (`TopBand`, D-159). Touch targets are ≥ 44px and primary CTAs are 56px. The only deviations from the DS and prototype are documented in `docs/DECISIONS.md` (for example, the AA contrast overrides in D-010). Do not restyle beyond them.

## Responsive rule: mobile-first is not a fixed mobile viewport

- Phones (320–599px) are the primary design. From 600px the app fills the viewport, and content keeps a readable column on the DS grid (margins 16/36/64). Choose each screen's column with `ScreenLayout width="form" | "reading" | "wide"` (480/800/1008), and use `card` for single-question screens. Never reintroduce a phone-width frame.
- Wider screens get **no new features**: the same hierarchy, at most two columns, the roster always a row list (never a table), primary actions 280px and centred.
- **One header:** `AppHeader` (`src/features/shell`) on every signed-in screen: brand left, avatar top right (always the right-most control). Primary navigation is `journey.navTabs`: **Home · Reports** for instructors (Home owns today's classes) and **Home · Attendance · Reports** for the principal. It is the bottom nav on phones and a header row from 600px, never a sidebar. Class-marking task screens take their `area`/back target from `useAttendanceRoot()`. **Profile is not a destination:** the avatar opens `ProfileMenu`, the only profile entry point. Offline data lives under Reports (`/reports/offline`) for every user, the principal included (D-153): downloaded batches only where the user can mark students (`journey.offline.packs`; for the principal, `identity.principalCanMarkStudents`), otherwise the page is the sync status only (its Reports entry reads "Sync status"); the waiting list names staff marks and outbox corrections. See `docs/DESIGN_SYSTEM.md` → Responsive behaviour and D-045/D-046/D-052/D-056.

## Mock data and simulation

- `src/data/mock/*` holds deterministic master data (Govt ITI Pune, code **27410**: 5 trades, 17 batches, 417 students; a second institute in Nashik), history generated at read time for past working days (including the ES instructor's sessions), and six announcements. `seeds.ts` builds today's story relative to the current date; every seeded submission comes from a submitter who self-marked first, so Rajesh, Sanjay, Pradeep and Asha submit nothing until they mark themselves (D-152, mock schema 3).
- The mock DB (`src/repositories/mock/database.ts`) lives in localStorage namespace `ksk:v1`. It **reseeds automatically when the calendar day changes** and on schema bumps.
- Location, face-match outcome, camera choice, permissions, network, sync failure and speed come from a `SimulationSource`. Services wait a simulated network time (`simulatedDelay`, scaled by speed, 0 in tests) so loading states are real (D-059).
- **Face (D-048):** three seams.
  - `FaceCaptureService` opens the **real front camera** (getUserMedia). The demo can switch to a simulated one.
  - `LivenessService` is a **prototype movement check** with MediaPipe BlazeFace on the device, falling back to guided countdown captures.
  - `FaceMatchService` is **simulated** (`MockFaceMatchService`): it never compares faces.
  - Photos are in-memory only: never stored, never sent. Never describe any of this as secure biometrics or liveness detection in UI or docs. MediaPipe is pinned to 0.10.35 (1.x phones home, D-049).
- Location results carry `source: 'device' | 'simulated'`.
- `src/repositories/api/*` are typed stubs that throw `NotImplementedError` and document the endpoints each method will call.

### Data source: the shared Supabase backend or the on-device mock (D-143, D-144)

- **Two sources, one set of interfaces.** `NEXT_PUBLIC_DATA_SOURCE` is `supabase` or `mock`. Unset, the build uses Supabase when `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are both set, otherwise the mock (`resolveDataSource`, `src/app-shell/data-source.ts`). Only the publishable key reaches the browser: a client key protected by RLS. Never a secret or service-role key, never committed: values live in git-ignored env files (`.env.development`, `.env.development.local`) or the Vercel project. `npm test` and `npm run e2e` run on the mock (Playwright builds with `NEXT_PUBLIC_DATA_SOURCE=mock`).
- **Supabase** (project `ksk-attendance`, `ap-south-1`; see `docs/SUPABASE.md`) holds the server-owned data: master data, announcements, submissions, corrections, staff attendance, voice minutes and face-enrolment flags. Drafts, the offline queue, packs, verification passes, the session and preferences stay on the device (`ksk:v1`; preferences in `ksk-prefs`).
- **Offline-first.** A record is saved and locked on the device first, then pushed by the existing `SyncService`. Reads merge the server with the device's own records: a record still waiting to sync wins for its key, otherwise the server's copy wins. A unique-key conflict with another id is `rejected`: final, not retried, and the server's copy wins. Corrections go through a device outbox that drains at start, on reconnect and with every sync, and counts as pending; every device orders corrections by (timestamp, `seq`, id). A live read drops this device's *synced* records the server no longer has (after a shared reset); never pending or rejected ones, never offline. Offline reads answer from the last server rows cached in `ksk-cache:v1`.
- **Realtime.** One channel per signed-in institute on submissions, corrections, staff attendance and face enrolment emits the app's topics (`attendance`, `corrections`, `staff`, `face`) after a 300 ms debounce, so a second device updates without a reload.
- **Demo on Supabase** (demo builds only): the first device to boot each day seeds today's story through `ksk_seed_day`; the panel's **Data** row switches between "Shared (Supabase)" and "This device" (it reloads and signs out, and refuses while records wait to sync); a preset or Reset writes its story packs on either source; **Reset shared demo data** calls `ksk_reset_demo`. The reset and test clean-up functions are in `supabase/migrations/20261005041600_ksk_reset_functions.sql`, which the owner pasted once into the Supabase SQL editor (the MCP's confirmation gate declined its `DELETE`s); a project without them answers Reset with "Reset isn’t set up on the server yet".
- RLS is deliberately permissive for the demo (anon reads everything and inserts write-once records; D-144). Production needs real identity and RLS by institute and staff before any real data goes in.

## Reports and the register download (D-053, D-137, D-154)

Reports is one page for this month (D-053); the principal's reads Institute → Batch attendance → At-risk → Staff attendance → Offline data → More reports. There (`staff_summary` with the principal's staff view) the **Staff attendance** section (`StaffSection`, built by the pure `buildStaffOverview` in `src/services/report-staff.ts` through `ReportService.staffOverview`) shows this month to date: a summary card, then one row per staff member, lowest % first, with today's status and unmarked days kept apart (never counted absent); the % chip warns below `reports.staffThresholdPct` (default 90). The Institute card drops its staff figure while the section shows, and More reports keeps only the Correction log. With `reports.pdfDownload`, My batches and Batch attendance offer a **monthly attendance register** for a batch or a whole trade, for this month (to date) or last month: a 44px download icon on every batch row (the `Disclosure` `action` slot), "Download register" at the end of an expanded batch, and "Trade register" on each trade's label line (the `Section` `action` slot); "Staff register" in the Staff attendance section's action slot opens the same sheet with the staff scope (`buildStaffRegister` in `report-staff-register.ts` → `staffRegisterDocument`, the same register parts). The pipeline is `ReportService.registerMonths` / `register` → the pure builder `buildRegister` (`src/services/report-register.ts`, arithmetic shared with the leaderboard in `report-math.ts`) → the pure HTML builder `registerDocument` (`src/features/reports/register/*`) → `saveTextFile` (`src/lib/download.ts`). The file is self-contained (CSP `default-src 'none'`, the emblem embedded once, every name escaped) and prints on A4 landscape. A printed register is a table by nature; the "roster is never a table" rule is about screens. Inside an Android WebView (`isEmbeddedWebView`, `src/lib/platform.ts`) the app says downloading isn't available there yet and builds nothing.

## Voice Agent (D-078 to D-159)

An instructor marks a batch by speaking, in English or Marathi, mixed freely with taps; since D-139 to D-141 voice also serves the principal and does more than marking: own attendance, staff attendance, reports and insights, register downloads, announcements and opening screens. Corrections stay tap-only (the audit trail). The feature is called **Voice Agent** (D-145); code identifiers keep `voice*`. Design: `docs/voice/2026-10-02-voice-mode-design.md`. Code map: `docs/voice/REPO_MAP.md`. Operations: `docs/voice/RUNBOOK.md`. The tap flow keeps working at every moment; voice is optional.

- **UI (D-133, D-147).** One floating element, `VoiceFloat`, rendered once by `VoiceProvider` (inside `SessionGate`, behind `VoiceErrorBoundary`: a crash stops voice, logs `float crashed: <name>` and renders nothing, so the tap flow keeps working) on every signed-in screen where voice is available (instructor and principal; `VoiceProvider` shows it when `voice.plan()` is not null, never by role). It is **one viewport overlay**, portaled to `<body>` (`position: fixed`, `--z-voice`), that never changes a screen's layout: the round 56px mic button (the "Voice Agent" pill from 1136px), the voice card it grows into (`VoiceCard`: status as icon + text + colour, caption, Pause/Resume voice, Stop voice, Reconnect, push-to-talk) and the round mini status button share the bottom-right corner, 16px in (24px from 600px), at the same viewport x on every screen. `DockInset` (`registerDock` from `ScreenLayout`, `useDockInset`) lifts it above a pinned footer band or the bottom navigation (`--float-dock`); a dock that follows the content (an inline footer, a centred card from 600px) lifts it only when the widget would come within 8px of one of its actions. `<html data-voice-float>` gives screens scroll room instead of a reserved band (`--voice-reserve-block-end` = the widget's height + 32px; `.card` screens 0; inline-footer screens from 600px keep `--voice-reserve-resting` under their dock), so `main` is the same height with the button and the card and every row can scroll clear. Toasts sit above the widget, and with `html[data-demo-drawer]` it moves left of the open demo drawer (`--overlay-width-drawer`). Start stays synchronous in the click. **The compact card:** on phones one row of at most 88px (status toggle, the primary action as its icon below 480px, Stop, Minimize); from 600px a 360px two-line card of about 128px; the second caption, hints, push-to-talk and the minutes note open from the status. **Idle rest (R7):** the open card rests as the mini status button after 6 s (`CARD_IDLE_COLLAPSE_MS`) with no agent audio, no new caption and no pointer or focus in it, and opens again when the agent starts a new spoken turn or the status needs the trainer (paused, reconnecting, an error); never with push-to-talk on; a manual Minimize stays until tapped. **Statuses:** while the face camera holds the mic the card reads "Mic off for face check" (mic-off, neutral; no level bar, Pause or Hold to talk; Stop stays); "Working…" (clock, info) after a blocking tool call has run 400 ms with no agent audio. The pause action reads "Pause" (named "Pause voice"; "Use screen" collided with the agent's "look at the screen"). Filler captions (`<no speech detected>`, dots, dashes) are hidden. **Earcons** (`audio/earcons.ts`, `session-cues.ts`): "ready" at the first listening after connect, "saved" after an ok submit, self mark or staff mark, "ended" when voice stops; each ≤ 200 ms, quieter than speech, never over the agent's speech, no mute yet.

- **Model and SDK.** `gemini-3.8-live` through `@google/genai`, pinned to exactly `2.26.0` (never `@google/generative-ai`). In the browser the SDK is only in `src/services/voice/live/gemini.ts`, loaded by `import()` when a live session starts; on the server only `src/server/voice/token.ts` uses it. **Start-up prefetch (D-138):** when the idle button shows and `VoiceService.canWarm()` (live voice, online), `VoiceFloat` preconnects to the Gemini origin (`live/origin.ts`, no SDK) and, once per page load, `VoiceService.prefetch()` loads the transport module through the same memoized `import()`; `VoiceSession.open()` starts that import before awaiting the microphone. `?voiceDebug=1` logs `first audio N ms after start`. The client connects with the model the token was minted for (`VOICE_MODEL` in `src/server/voice/token.ts`); its own copy is only a fallback (D-131).
- **Browser-direct (D-078).** The browser connects to Gemini Live with a single-use token from `POST /api/voice/token` (`src/app/api/voice/token/route.ts`, helpers in `src/server/voice`). The server holds `GEMINI_API_KEY` (never a `NEXT_PUBLIC_` name, never committed, never logged). The page never sees the key. `VOICE_DISABLED=1` is the kill switch. There is no relay; a relay and Vertex are a later phase.
- **Config and the capability plan (D-139).** `voice.*` configuration (CONFIGURATION.md) → `journey.voice` → `compileVoicePlan(ctx, screenLanguage)` (`src/domain/voice/plan.ts`) once per voice session: the marking `FlowPlan` (`compileFlowPlan`; null for the principal) beside `capabilities`: `selfAttendance`, `reports` (`instructor` | `institute` | null), `staffMarking` with `staffStatuses`, `announcements`, `downloads` (`reports.pdfDownload`) and `navTargets` (home, attendance, reports, my_attendance, offline, staff_attendance, announcements, as the journey has them). Marking by exception needs a Present default: any other default starts a roll call, whatever `voice.markingStyle` says (D-117). The prompt (`prompt.ts`, one section per capability in `prompt-capabilities.ts`), the tool list (`tools.ts`) and every `[APP]` text are built from the plan. A disabled capability has no tool and no prompt line. With a marking plan `createExecutor` runs the marking executor; without one, the overview executor (`executor-overview.ts`: `get_status` for today's state, `navigate`, `get_announcements`, `end_voice_session`, plus the report and staff tools). D-087 (instructor Home only) is superseded.
- **Greeting and own attendance first (D-151, D-152).** The first line is app-filled (`greeting.ts`) from `dayPart(ctx.wallClock.now())` and the first name, or the salutation for the principal ("Hi Rajesh, good morning.", "Good evening, Principal."); the kickoff tells the model to say it exactly, then today's state, then "How can I help?". With `capabilities.selfAttendance` and no own record today, every fresh start, on any screen, asks "Please mark your attendance first. Shall I start?" instead (no auto-open); with `journey.staff.selfFirst` it is required and `select_trade` / `select_batch` answer `SELF_FIRST`; without the rule it is a suggestion and "later" continues. On a yes, `mark_my_attendance`; after the self mark the same turn leads on to the students, and a batch it opens reuses the self pass within `selfPassReuseMinutes`. A refresh or Reconnect before the trainer answers asks again, never the trade. The principal's kickoff names the staff not marked, "including you".
- **Marking flow (D-134, D-135, D-156).** Voice reads only sessions that can be marked now (`markableNow`: open and `canMark`); a named later or closed batch is refused with its reason (`WINDOW_NOT_OPEN`, `WINDOW_CLOSED`). The trade offer names only the trades with a batch open and not yet marked ("Right now only Electrician and Fitter have batches open and not yet marked. Which one?") and, asked about the others, gives each one's reason (all submitted, next opens at a time, windows closed); SCOPE no longer primes "I can only help with". With exactly one markable session at a fresh start, no trade step and no own attendance pending, the kickoff opens it itself (auto-open, through `select_batch`, once the connection is live). By exception the agent asks only who is absent ("anyone else?"), one short sentence per turn (≤ 12 words; under 8 in a roll call), and the submit question is one line with the counts and "it is final". After a submit it offers the next markable session by its id, from the trainer's whole board across trades (same trade first).
- **No auto-end (D-142).** When nothing can be marked, voice says why in one line and asks "How can I help?" (mr "मी काय मदत करू?", which replaced "What do you need?", D-151); STYLE still bans unprompted offers of help; after the last submit it says so and waits. `end_voice_session` only when the trainer asks; the idle timeout still ends a silent session.
- **Reports and insights (D-140, D-154).** With `capabilities.reports`: `get_reports_overview`, `get_batch_report`, `get_student_report`, `get_at_risk` and, with `capabilities.reportSections.staff` (the principal), `get_staff_report` (this month's %, the five lowest, the number not marked today, from `ReportService.staffOverview`, the builder the overview's staff figure also uses) return figures the app computed (month figures from the register), so the model never does arithmetic; the answer is one or two short sentences and opens nothing. On a yes, `show_report` shows what was last answered. `download_register(target, month)` (with `capabilities.downloads`) opens the register sheet with the batch, trade or staff scope and month chosen; the trainer still taps Download. Report tools return names as the Reports screen does, without a verification (INV-16 is about marking).
- **Own and staff attendance (D-141).** With `capabilities.selfAttendance`: `get_my_attendance`, and `mark_my_attendance`, which opens `/me/attendance`, follows the screen's own location and face check and saves through `StaffAttendanceService.markSelf` only after the pass (or at once when a pass exists or no check is configured); no override. With `capabilities.staffMarking` (the principal): `get_staff_today` (counts, at most five unmarked names, the principal's own row first as "you", never their name in the third person), `mark_staff(staff, status)`, which needs an executor-issued confirmation code and saves through `markByPrincipal` ("me", "myself", "mujhe", "meri", "मला", "माझी" name the user), and `mark_remaining_staff(status)` for everyone else at once with one coded yes ("Mark the other 4 staff present? It is final."). The staff screen outlines the person asked about (`focus_staff`); after a save the agent offers the next unmarked person by name, with that person's own code (one yes per person). A self mark always stands (D-156).
- **Tools.** Every declaration sets `behavior: 'BLOCKING'`. A result is sent as `{ id, name, response: { output: result } }`, with the `id` key always present (the SDK throws without it; a call without an id is answered with `id: undefined`). One `sendToolResponse` per `toolCall`, in the model's order. The calls of one message run one at a time in `toolCallOrder` (`mark_remaining` after the per-student marks, `mark_remaining_staff` after `mark_staff`), and calls from consecutive messages share one per-connection queue (the SDK does not await `onmessage`). A throwing handler answers `INTERNAL` with the "say sorry and repeat your last question" instruction; an unknown name answers `UNKNOWN_TOOL`. Results are `{ ok, instruction, … }` plus the snapshot; model-facing enums are uppercase and mapped at the executor boundary (`parseModelStatus`).
- **Executor (D-079).** `createExecutor` (`src/services/voice/executor.ts`, handlers in `handlers/`) calls only services: `AttendanceService`, `VerificationService` and `MarkingDraftService` for marking; `ReportService` and `AnnouncementService` read-only; `StaffAttendanceService` for own and staff marks. Every rule that holds for a tap holds for voice. It has no browser globals. Every handler re-reads the draft after each `await`.
- **Languages (D-080, D-146).** The agent speaks only `voice.languages` (built into the LANGUAGE block from `plan.languages`): it opens in the opening language, replies in the language of the trainer's last full sentence when that is a voice language, understands mixed Hindi, and never replies in Hindi.
- **Voice and persona (D-155).** One fixed prebuilt voice per language: `voice.voiceNames` (product `{ en: 'Achernar' }`, Maharashtra `{ en, mr: 'Achernar' }`, a soft female voice; only the 30 prebuilt names in `src/domain/voice/voices.ts`, and only for a language in `voice.languages`), with `voice.voiceName` (Achernar) as the fallback. The session uses the opening language's voice for its whole life (reconnects and swaps reuse it; a Live connection cannot change voice). The **VOICE AND TONE** block comes right after the identity line: calm, soft and warm at a normal speaking volume, an unhurried even pace, Indian English with Indian pronunciation of names, Pune Marathi with feminine first-person forms, the same voice and tone in every reply; STYLE opens "Be brief and efficient, never rushed". No gain or pitch change. The agent's name in the prompt and the caption is "Voice Agent" (mr "व्हॉइस एजंट").
- **Text to the model.** The kickoff, `[APP]` events and typed text go through `sendRealtimeInput({ text })`; audio through `sendRealtimeInput({ audio: { data, mimeType: 'audio/pcm;rate=16000' } })`. Never `media`, never `sendClientContent`. Send `audioStreamEnd` whenever the microphone pauses. Model-facing strings are English, except the fixed Marathi greeting, help question and own-attendance ask (`greeting.ts`) that the model is told to say exactly; UI strings are `voice.*` keys in `en.ts` with Marathi in `mr.ts`.
- **Live config.** Audio replies only, input and output transcription on, `contextWindowCompression` 25 000 / 8 000, `sessionResumption: {}` or `{ handle }` (never `transparent`), VAD start LOW / end HIGH / prefix 100 ms / silence 500 ms. Never set `thinkingConfig`, `proactivity`, `enableAffectiveDialog`, `generationConfig` or `speechConfig.languageCode`, and never put `httpOptions` inside the `LiveConnectConfig` (`liveConfig` in `live/transport.ts` is the one place).
- **Audio.** Input PCM16 mono 16 kHz in 640-sample (40 ms) chunks from the same-origin worklet `/voice/mic-worklet.js`. Output PCM16 mono 24 kHz, played gapless. Process every part of every server message. On `interrupted`, flush playback first and play nothing from that message. Both AudioContexts are created and `resume()`d synchronously in the click handler, before any `await` (`VoiceService.start` is synchronous for that reason). The SDK's `ai.live.connect()` never rejects when setup fails, so `gemini.ts` races it against the first close and a 10 s timer; `LiveTransport.connect()` rejects in both cases.
- **goAway (`session-swap.ts`).** At the first quiet moment (nothing playing, no trainer utterance unanswered, no tool running) or at `timeLeft − 2.5 s`: fetch a fresh token while the old connection still works, close the old one, connect with the resumption handle, send the executor's refresh text (spoken facts, never "stay silent"), then replay the held mic audio (at most 3 s), preceded by the 0.64 s pre-roll only after a quiet-moment swap (D-121). A pause the swap held reaches the new connection as the pause text. Generation numbers drop answers for an old connection. An unexpected close shows **Reconnect** on the card (new AudioContexts need a tap); it resumes with the handle once, then without it. Three failed connects in a row (across Reconnect taps) stop voice with `failures` (D-114).
- **Confirmation tokens (D-082).** `submit_attendance`, `mark_remaining` and `mark_staff` need a code the executor issued with its question: bound to the action, arguments, draft revision and connection, valid 2 minutes, accepted only after the model's asking turn ended (`turnComplete` or `interrupted`) and a new trainer turn began after it (`TrainerTurns`, `src/services/voice/trainer-turns.ts`; late transcript fragments never count, D-112), voided by any draft change, a new connection, expiry, or (for the submit code) the flow leaving the review (D-110). A `mark_staff` code is bound to the staff member and status and to today's staff records (any staff change voids it), and is used once (D-141). A `mark_remaining_staff` code has its own ticket, bound to the exact set of unmarked staff ids, the status and today's staff records; any staff change voids it, and it is used once (D-156). Never a boolean the model fills in. The submit question carries its code, so one clear yes submits (D-102). Not configurable. The clock for the TTL is real elapsed time (`performance.now()`), not the demo clock.
- **The live draft (D-084).** One `MarkingDraftService` draft per session key sits behind taps and voice: marks, the source of each trainer mark (`tap` or `voice`, at most 160 characters heard, kept in memory only while `voice.transcriptRetentionDays` is 0: the saved draft has `{ via, at }`, D-113), a revision and change events. While either submit (the screen's or voice's) saves, the draft refuses every mark (`beginSubmit` / `whileSubmitting`); voice answers `SUBMITTING` and issues no code (D-111). Defaults and presets (OJT, carried leave) are not trainer marks. OJT stays locked for voice (D-101). Leaving a batch never drops marks, so there is no "marks will be lost" question (D-083). `AttendanceService.saveDraft` remains for integration tests only.
- **Action Bus (D-085).** The screen changes only from typed, sequenced bus events, applied by `useActionBus` and the screens that own the state: `navigate`, `show_trade`, `focus_student`, `verify_retry` (carries the check's purpose, `session:<key>` or `self`), `end_voice`, `show_announcements` (`AnnouncementBanner`), `show_batch_report` and `open_register` (`BatchesSection`), `show_at_risk` (`AtRiskSection`), `show_staff_report` and `open_staff_register` (`StaffSection`), `focus_staff` (`StaffScreen`), `self_marked` (`SelfAttendanceScreen`) and `saved` (the session's "saved" earcon). The screen-owned events replay for a screen that mounts after voice's navigation, bounded by the next `navigate`. Never from model text. A navigation to the URL already shown is skipped. A running session ends itself after its goodbye line: `end_voice` does not `stop()` it.
- **Taps flow back.** A tap on the draft, a tap navigation (`useScreenSync` → `onScreen`), a trade tapped on Home's switcher and verification events (`VerificationService.subscribe`) reach the model as `[APP]` texts. Their texts are dropped (not queued) while the session is paused or not live, but the executor still follows them quietly (no question, no code, no navigation), also while Reconnect shows; the kickoff runs on the tool queue after them and reads the moved flow (D-122).
- **Verification (D-086, D-148).** The existing full-screen gateway stays. Student fields are returned only after the pass; `openRoster` and `submit` enforce INV-16. The microphone goes off the moment the face camera opens, and the live stream renders only while the face step runs (facing, matching); "Identity verified" shows a still visual. Location has no override. Distances in `[APP]` texts are formatted by the app, not the model. The agent's check line names the steps and the camera ("Checking your location, then please look at the camera.").
- **Pacing (D-148).** Check texts never interrupt the agent: they go through a polite outbox (`session-outbox.ts`) that sends when the agent is quiet (nothing played for 300 ms, no model turn in progress, no reply owed); the camera-on text is dropped if the agent is not quiet within 4 s, the pass, batch-opened, self-passed and failure texts are sent anyway after 3 s; pause, stop, loss and a new connection drop held texts, and the outbox never runs on the tool queue. The camera never flushes the player. The screen paces itself with `useVoicePace().settle(cap, signal)` (the narrow `VoicePaceContext`, `{ live, settle }`): `settle(4000)` before the camera, a 1.5 s hold (0.9 s without live voice) and `settle(3000)` at "Location verified", the hold then `settle(3000)` before the grant; caps scale with `simulation.speed`, and closing the screen ends every wait. **Automatic resume:** a user pause made while a check runs (the flow in VERIFY for it, the trainer's own check, or the camera on) ends on that check's pass, with the pass's own text (`resume (auto)`); a hidden-page pause that began during a check resumes when the page shows again. Every other pause keeps "until Resume".
- **Caps (D-089).** Client-enforced: minutes per session (across reconnects), daily minutes per trainer (`VoiceUsageRepository`), idle timeout, 40 tool calls a minute, 5 failures in a row, 3 failed connects in a row. Trainer speech, taps, screen and verification signals, tool calls and the page becoming visible again are activity; only a Pause on a visible page holds the idle clock. A hidden WebView stops the microphone and pauses after 20 s, and that pause keeps the idle clock running (D-119, D-120); while a camera permission prompt is pending the hidden timer is 60 s instead (D-148). The server enforces token expiry, a per-IP limit (D-107), the Origin check and the kill switch.
- **Privacy and logs.** No audio is stored. Captions and the heard text stay in memory (`voice.transcriptRetentionDays` 0, D-113). Never log audio, tokens, the API key, the WebSocket URL, student names or the `heard` text. Debug lines are `console.info('[voice] …')` through `voiceDebug()` (`src/services/voice/debug.ts`), ids and codes only: always on in a development build, behind `?voiceDebug=1` in production; once seen, the flag holds for the rest of the page load, across the app's own navigation (D-130, D-158). They include `interrupted`, `pause (user|hidden)`, `resume (tap|auto)`, `camera on|off`, `check text held|sent|dropped` and `earcon <kind>`. Never `console.error` for an expected condition: E2E fails on any console error. Say in the UI that voice is processed by Google; do not call it secure biometrics.
- **Scripted transport for tests and demos.** `ScriptedLiveTransport` and `SilentAudio` (`src/services/simulated/voice.ts`) stand in for Gemini and the microphone when `simulation.voice === 'scripted'`. `window.__kskDemo.voice` plays the model (`toolCall`, `speak`, `emit`, `texts`, `responses`, `drop`, `goAway`, `denyMic`, `playing(on)` to make the agent "speak" so the pacing can be tested, `earcons()` to read the cues played); a scripted confirmation needs `emit({ turnComplete: true })` before the trainer's `speak(…)` (D-112). CI and `npm run e2e` need no key, no network and no microphone. Model-facing wording (prompt, instructions, `[APP]` texts) is tuned against the live model: change it only with a `npm run test:voice-live` rehearsal (the full suite, 40 conversations), and hear voice UI changes end to end with `npm run voice:ui-rehearsal`.
- **Demo.** Every preset turns voice on, the principal's included, and a fresh or Reset demo has voice on (D-157); presets keep the presenter's voice model; `PRESETS_VERSION` re-applies a stored preset once (D-106, D-108). Voice demo code stays in `src/demo`, and `npm run check:demo` asserts it does not ship.
- **Local dev (D-158).** The composition root is disposable: `AppContainer.dispose()` (idempotent) stops sync, a running voice session, the Supabase Realtime channel, the connectivity listeners and boot's subscriptions; `AppProviders` disposes the runtime its effect booted (Strict Mode's second boot included), and `// @refresh reset` at its top rebuilds the container on a services, repositories, config or domain edit. In a development build only, the token fetch waits 20 s (8 s in production) and the token route allows 200 tokens per 10 minutes (20 in production, D-107).

## Deployment

The app is Vercel-ready and **prepare-only: do not deploy unless the user asks**. `npm run build` prerenders every page as static and needs no secrets at build time. The one route handler, `POST /api/voice/token` (nodejs runtime), reads the server variables `GEMINI_API_KEY`, `VOICE_DISABLED` and `VOICE_ALLOWED_ORIGINS` at request time: set them in the Vercel project, never with a `NEXT_PUBLIC_` name. Without a key the route answers 503 and only Voice Agent is unavailable; see `docs/voice/RUNBOOK.md` (including what to set up before a key goes on a public deployment). The Supabase data source needs only `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (a client key protected by RLS, so a `NEXT_PUBLIC_` name is right for it), inlined at build time; without them the build uses the on-device mock (D-143, `docs/SUPABASE.md`). The build is the stakeholder demo unless `NEXT_PUBLIC_DEMO_MODE=false` is set: `next.config.ts` defaults it to `true`, because `.gitignore` keeps `.env.production` out of git and Vercel builds from git (D-067). Set it to `false` in the Vercel project for a real rollout once the API repositories exist. `.env.example` documents the flag.
