# Configuration

Every state difference is a value in `AppConfiguration` (`src/config/types.ts`), never a branch on a state or a person in the UI. This page lists every option, its Maharashtra value, and **what a user actually sees** for each setting. Registry keys in parentheses are the PRD's names (PRD §14, §17–§21).

## How a configuration is resolved

```
PRODUCT_DEFAULTS (src/config/defaults.ts)
  → state floor (src/config/states/maharashtra.ts)            every key has a state value
  → district layer → institute layer                          only keys listed in overridableKeys
  → demo: persona patch → demo-panel changes                  demo builds only
  → normalize (Present and Absent are always in status sets)
  → validate (src/config/validate.ts)                         invalid combinations are rejected
  → deriveJourney (src/config/journey.ts)                     the only input screens use
```

Maharashtra opens three keys to narrower scopes: `time.shiftWindows`, `verification.fenceRadiusM` and `voice.enabled`. `ConfigurationService.resolveFor(institute, staffId)` returns the resolved configuration for a session. When the configuration changes, the session reloads, verification passes are cleared, and every screen re-renders from the new journey.

To add a state, create `src/config/states/<state>.ts` with a `StateConfiguration` (base = `PRODUCT_DEFAULTS` plus that state's sheet), load its master data, and deploy. No screen changes are needed.

| `faceRetryLimit` (verify.face_retry_limit)   | `null`      | `null`: unlimited _Try again_. | `selfPassReuseMinutes` (verify.self_pass_reuse_minutes, extension, D-152) | `10` (product default `0`) | One check, not two. The same holds when voice opens the class. A self pass that lacks a check the class needs (for example, no face) never stands in. `0`: no reuse; every class runs its own check. A whole number from 0 to 60 |

If both `geoMode` is `off` and `face` is `false`, there is no verification screen at all: selecting a batch opens the list directly.

The reuse window is measured on the injected clock (`ctx.clock`), from the time the self pass stores (`grantedAt`, with the checks it covered, DATA_MODEL → `VerificationPass`). A pass stored without its checks is never reused. In a demo with the fixed clock (10:15 by default) the clock does not move, so a self pass reads as 0 minutes old and keeps opening classes all day; move the demo clock to show the limit. Production uses the device clock.

Offline is for everyone since D-153: `journey.offline.enabled` follows `offline.enabled` for every user. Downloaded batches are gated separately by `journey.offline.packs`: offline on, and for the principal also `identity.principalCanMarkStudents` (on in Maharashtra). Packs gate the downloaded-batches section, the download screen (`/reports/offline/download`, which redirects without packs) and pack download and refresh, so offline never exposes a batch the user could not mark online (INV-25). Without packs, Offline data is the sync status only (the Sync pending card and "All attendance synced"), and its Reports entry is titled "Sync status". The principal's staff marks made offline are queued and synced like any record. Packs and the queue belong to the device, not the user. A record can be corrected only after it has synced; on the Supabase source a correction made offline waits in the correction outbox and is listed as "Correction · {student}" (on the mock, corrections are never pending).

## Voice: `voice` (extension, D-078–D-089, D-113, D-117, D-119, D-134–D-142, D-152, D-155)

Voice Agent lets an instructor mark a batch by speaking, in English or Marathi, and since D-139 serves the principal too. What it can do comes from the rest of the configuration (the capability plan, below). Taps keep working at every moment, and where it is off it is absent, not hidden. The design is in `docs/voice/2026-10-02-voice-mode-design.md` (§6).

| Option                                                      | MH                              | Values → what the user sees                                                                                                                                                                                                      |
| ----------------------------------------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled` (voice.enabled)                                   | `false` (institute-overridable) | `true`: the floating **Voice Agent** button on every signed-in screen, for instructors and the principal (D-133, D-139); its hint follows the capability plan ("Speak to choose a batch and mark attendance." with marking, "Speak to ask about attendance, reports and staff." without). `false`: no Voice Agent anywhere. The demo presets switch it on                                 |
| `languages` (voice.languages)                               | en, mr (product default `en`)   | Languages the agent speaks; it replies only in these, understanding Hindi or other mixed words without ever replying in Hindi (D-146). | `defaultLanguage` (voice.default_language)                  | `en`                            | Opening language when the screen language is not one of `voice.languages`. Maharashtra opens one voice key to narrower scopes: `voice.enabled`. The languages, marking style, voice and limits come from the state floor. `journey.voice` is `{ enabled, languages, defaultLanguage, markingStyle, voiceName, voiceNames, limits: { sessionMinutes, idleSeconds, dailyMinutes } }`, and `enabled` is true when `voice.enabled` is on and the language guard holds (since D-139 the home variant no longer matters): `voice.languages` is a non-empty subset of `i18n.languages` **and** `voice.defaultLanguage` is one of `voice.languages`. `validateConfiguration` reports a broken language set (`voice_languages`, `voice_default_language`), but it runs in tests and tooling, not at runtime, so `deriveJourney` repeats the check and fails closed: a configuration with `defaultLanguage: 'en'` and `languages: ['mr']` gets no Voice Agent rather than an agent that opens in a language it may not speak (`tests/unit/config/voice-config.test.ts`). Only the language guard is repeated at runtime. A sheet with `markingStyle: 'exceptions'` and a default other than Present starts a roll call (`compileFlowPlan`, D-117), and an out-of-range limit runs as configured, so each state sheet must pass `validateConfiguration` in its tests. Not configurable (fixed in code): confirmation before submit, before bulk marking and before a staff mark, verification before names, no location override, no corrections by voice.

| `announcements` | `announcements.enabled` | Read today's notices and open them (D-139) |
| `navTargets` | the journey's screens: Home, Attendance (principal tab), Reports, My attendance, Offline data (for the principal too since D-153), Staff attendance, Announcements | Open a screen when asked |

In Maharashtra the instructor gets marking, own attendance, reports, downloads, announcements and screens; the principal gets today's overview, staff marking, institute reports, downloads, announcements and screens.

## Build environment: the data source (D-143)

Not part of `AppConfiguration`: these are build-time environment variables, inlined by Next because they carry the `NEXT_PUBLIC_` prefix. Values live in git-ignored env files (`.env.development`, `.env.development.local`) or the Vercel project settings; `.env.example` lists the names only.

| Variable | Values → what the user sees |
|---|---|
| `NEXT_PUBLIC_DATA_SOURCE` | `supabase`: shared live data in the Supabase project; every device sees the same records, and other devices refresh within about a second (Realtime). `mock`: data on this device only (`ksk:v1`), as before. Unset: Supabase when both variables below are set, otherwise the mock. Asking for `supabase` without them stays on the mock |
| `NEXT_PUBLIC_SUPABASE_URL` | The project URL (`https://<project-ref>.supabase.co`) |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | The project's publishable key: a client key protected by Row Level Security (D-144). Never a secret or service-role key |

The choice applies to demo and demo-off builds alike. Demo builds also offer the panel's **Data** row ("Shared (Supabase)" or "This device"), stored in the demo state and applied after a reload. `npm test` and `npm run e2e` run on the mock (Playwright builds with `NEXT_PUBLIC_DATA_SOURCE=mock`). See `docs/SUPABASE.md`.

## Validation rules (`src/config/validate.ts`)

These are errors:

- `status_set_core`: Present or Absent is missing.
- `half_day_halves_without_half_day`: halves are on but Half day isn't in the status set.
- `fencing_without_windows`: a shift has no window while time fencing is on.
- `face_without_enrolment`: no instructor has an enrolled face.
- `timetable_without_data`, `period_without_data`: the timetable model or period marking is on without timetable data.
- `batch_without_assignments`: the batch model is on but nobody has assigned batches.
- `fence_radius`: the radius is not a positive number.
- `default_language`: the default language is not in the list.
- `language_count`: the state does not ship 1–3 languages.
- `staff_no_path`: staff attendance is on but both capture paths are off.
- `self_before_students_needs_self_marking`: own attendance first is on, but staff attendance or self-marking is off.
- `self_pass_reuse_minutes`: the self-pass reuse is not a whole number of minutes from 0 to 60.
- `threshold_range`: the at-risk threshold is outside 1–100.
- `staff_threshold_range`: the staff threshold is outside 1–100.
- `trend_months`: the trend is not a whole number of months from 0 to 12.
- `report_window`: the report window is not a whole number of days from 7 to 120.
- `at_risk_min_days`: the at-risk minimum is not a whole number from 1 to the report window.
- `voice_languages`: the voice languages are empty, or include a language that is not in `i18n.languages`.
- `voice_default_language`: the voice default language is not one of the voice languages.
- `voice_marking_style`: voice marks by exception but the default status is not Present.
- `voice_name`: `voice.voiceName` or a `voice.voiceNames` entry is not one of the 30 prebuilt Gemini voices.
- `voice_names_language`: `voice.voiceNames` names a voice for a language that is not in `voice.languages`.
- `voice_limits`: a voice limit is not a positive whole number, the idle timeout is under 30 seconds, or the transcript retention is not a whole number of days (0 or more).

These are warnings:

- `twice_with_half_day`: twice-daily marking and Half day answer the same question.
- `face_with_offline`: face matching may need the server while offline.

## Demo overrides

In demo builds each persona carries a small patch (for example, the Timetable persona sets `mapping.model: 'timetable'`, `marking.frequency: 'period'` and `time.fencing: true`). The panel then layers the presenter's changes on top. Real deployments have one mapping model per state, and the persona patches exist only so one demo institute can show every model.
